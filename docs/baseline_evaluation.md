## Agent 循环

当前 Agent 是确定性的多策略自评估系统：

```text
解析 TSV
  -> 计算 case 画像
  -> 生成多个任务分区候选
  -> 针对候选分区运行骑手分配策略
  -> 用期望惩罚和 assigned 成本做代理评分
  -> 保留当前最优方案
  -> 对低意愿/骑手稀缺 case 做少量策略邻域探索
```

它不接入外部模型。评测环境没有稳定 API Key 和网络，因此所谓 LLM 直接推理目前保留为算法库入口，并退化为确定性规则策略。

## 已实现策略

- `greedy`：快速构造合法解。
- `pair_first`：优先选择二任务合单，减少任务组数量。
- `minimum_group`：在骑手稀缺时尽量压低任务组数。
- `low_willingness`：低意愿场景下更重视失败概率和备选骑手。
- `hybrid_split`：低意愿场景下比较合单与拆单的代理成本，必要时放弃合单。
- `component_dp`：按高价值合单边构造连通组件，在组件内用 bitmask DP 求任务分区。
- `global_assigner`：从空方案出发，以边际收益为准给任务组分配不重复骑手。
- `local_search`：在时间预算内做保守替换，保持覆盖不下降。
- `low_assignment_finish`：低意愿场景在最终输出前比较 seeded/global 两类分配器，并做小预算骑手替换、移动和交换。

## 主要瓶颈

### `low_willingness_seed501`

低意愿 case 的问题不只是价格高，而是失败概率高。当前策略通过拆单和更多备选骑手降低失败惩罚，但线上分数仍高于均值很多。

后续方向：

- 为低意愿单独建立更真实的代理目标，避免本地指标过度偏向生成器。
- 探索“先保证每个任务有可接受成功率，再压低成本”的两阶段分配。
- 控制合单使用，只保留成功率和成本同时占优的合单。

当前新增的低意愿收尾优化只在 `_is_low_willingness_case` 命中时启用，避免影响普通 large/medium 的耗时。它在本地代理集上将 `low_willingness_seed501` 从 `1688.912` 降到 `1653.277`。

### `scarce_couriers_seed401`

骑手稀缺 case 的关键是每个骑手的机会成本。当前 `component_dp + global_assigner` 已明显降低该项，但仍不是最优。

后续方向：

- 在组件 DP 中加入骑手冲突的影子价格。
- 对稀缺 case 使用更小、更精确的组件，避免局部最优消耗关键骑手。
- 增加任务组之间的二次交换，如 `2 -> 2`、`3 -> 2` 分区重排。

## 时间约束

当前大样例线上耗时约 `6.4s`，仍低于 `10s`，但已经不适合继续盲目扩宽 beam 或策略网格。后续优化原则：

- 大样例新增策略必须有明确 gate。
- 低意愿和骑手稀缺 case 可以使用更多预算。
- 通用 medium/large 不再重复评估明显相似的分区。
- 所有新策略必须通过 `python -m pytest` 和本地代理评估。
