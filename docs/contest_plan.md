# 比赛任务与实施计划

## 赛题当前定义

根据官方样例，比赛输入是一张预计算候选表。每一行表示一个可选派单方案：

```text
task_id_list	courier_id	total_score	willingness
T0037,T0039	C028	52.016	0.582
```

因此当前比赛任务是一个组合优化问题：

- 从候选“任务组合-骑手”边中选择若干条。
- 同一个任务最多被覆盖一次。
- 同一个骑手最多被使用一次。
- 优先覆盖更多任务。
- 在覆盖任务数相同或相近时，让总分 `total_score` 尽量低。
- 可将 `willingness` 作为次级 tie-breaker 或期望收益修正项。

提交代码只需要实现根目录 `solver.py` 中的：

```python
def solve(input_text: str) -> list:
    ...
```

返回格式：

```python
[("T0037,T0039", ["C028"]), ("T0012", ["C073"])]
```

## 数据规模

以 `examples/large_seed301.txt` 为例：

| 指标 | 数值 |
| --- | --- |
| 候选行数 | 33780 |
| 任务数 | 40 |
| 骑手数 | 80 |
| 单任务候选 | 3200 |
| 双任务合单候选 | 30580 |
| 时间限制 | 10 秒/算例 |

这个规模适合先用高质量贪心和局部搜索，再尝试 bitmask 动态规划、分支定界或整数规划风格的搜索。

## 必须实现

- TSV 输入解析：识别表头、跳过非法行、解析任务组合、骑手、分数和意愿。
- 元数据计算：统计候选数、任务数、骑手数、分数分布、意愿分布和最大合单规模。
- Agent 决策：根据输入规模和候选结构选择算法。
- 输出生成：返回 `list[tuple[str, list[str]]]`。
- 冲突检测：保证任务不重复、骑手不重复。
- 本地评估：统计覆盖任务数、总分、平均意愿、使用骑手数。
- 算法库：贪心、ILP 风格分支定界、统计启发式搜索、LLM 直接推理占位策略。
- 提交入口：根目录 `solver.py` 自包含，不依赖安装包。
- 测试：覆盖解析、输出格式、冲突约束、大样例烟测。

## 当前 Agent 循环

```text
获取 input_text
  -> 解析候选数据
  -> 计算元数据
  -> Agent 选择算法
  -> 运行对应算法
  -> 输出提交格式结果
```

当前决策规则：

- 有大量合单候选时走 `heuristic_search`。
- 普通输入走 `greedy`。
- `branch_bound` 保留为实验算法，不作为默认提交路径。
- `llm_direct_reasoning` 暂保留为算法库接口，评测时不调用外部 LLM。

## 可选优化

- 平均成本贪心：按 `total_score / task_count` 选择，优先利用合单候选。
- 任务覆盖优先：用大常数奖励覆盖任务数，避免为了低分少接单。
- 局部搜索：替换一条候选为两条或多条候选，降低总分或增加覆盖。
- Beam Search：按任务覆盖 bitmask 搜索，保留前 K 个低成本状态。
- 分支定界：对 40 个任务建立 bitmask，上界剪枝。
- 多策略竞速：10 秒内运行多个策略，选覆盖最多、总分最低的方案。

## 当前 baseline 评测

本轮 baseline 已完成官方评测 `10/10`，所有样例任务覆盖率均为 `100%`，平均惩罚分数为 `2102.16`。

详情见 [baseline_evaluation.md](baseline_evaluation.md)。

## 两人分工建议

### 成员 A：算法负责人

- 设计目标函数和评估指标。
- 实现平均成本贪心、局部搜索、bitmask/beam search。
- 对大样例做误差分析，比较覆盖任务数、总分和耗时。
- 维护候选冲突索引和搜索剪枝逻辑。

### 成员 B：工程与提交负责人

- 维护 `solver.py` 自包含提交入口。
- 完成 TSV 解析、结果校验、测试和本地运行脚本。
- 建立实验记录格式，保存每种策略的分数和耗时。
- 负责最终代码压缩、提交验证和回归测试。

## 里程碑

### M1：官方格式 Agent baseline

- 完成 TSV 解析。
- 完成元数据计算与 Agent 决策。
- 完成无冲突算法输出。
- 本地样例可跑通并覆盖所有可覆盖任务。

### M2：评估与实验闭环

- 增加本地评估函数。
- 增加策略对比脚本。
- 固化大样例运行结果。

### M3：搜索优化

- 引入 bitmask 表示任务集合。
- 增强分支定界、局部搜索或 beam search。
- 在 10 秒限制内稳定优于 baseline。

### M4：最终提交

- 精简 `solver.py`。
- 确认无第三方依赖。
- 在全部样例上运行，保留最佳策略参数。
