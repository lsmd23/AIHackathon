# 赛题实现方案

## 赛题理解

比赛要求构建一个 AutoSolver Agent 系统，用于自主求解配送任务分配问题。输入包括配送订单、可用骑手，以及任务-骑手组合的预计得分或成本信息。系统需要在限定时间内输出当前最优分配方案。

核心目标有两个：

- 接单数量尽量最大化。
- 在接单数量相同或相近时，总分数/总成本尽量最小化。

同时需要考虑：

- 配送时间、距离、骑手意愿。
- 平台允许拒绝订单。
- 一个订单可同时指派给多位骑手，最先接起订单的骑手获得订单。
- 合单配送，即多个订单可合并给同一骑手。
- 每次测试用例需要在 10 秒内给出结果。

## 初始技术路线

第一阶段不直接依赖大模型完成最终求解，而是先搭建可验证的求解框架：

1. 数据建模：统一订单、骑手、分配、方案、评分结果的数据结构。
2. 基线策略：实现贪心分配，确保任何输入都有稳定输出。
3. 评分模块：独立计算接单数量、总成本、拒单数量等指标。
4. Agent 编排：让 Agent 根据历史表现选择不同策略，保留后续接入 ILP、启发式搜索、LLM 推理的接口。
5. 实验闭环：每轮运行记录策略、耗时、得分，后续根据表现调整策略。

## 需要实现的部分

### 必做

- 输入解析：读取比赛给定的数据格式，并转换为内部模型。
- 输出生成：按比赛要求输出订单-骑手分配结果。
- 评分函数：本地复现比赛目标，便于快速迭代。
- 贪心 baseline：作为最小可用求解器和回归测试基准。
- 策略接口：统一不同算法的输入输出。
- Agent 控制器：管理策略选择、运行超时、结果评估和最佳解保留。
- 测试用例：覆盖数据解析、评分、非法分配、基础策略行为。

### 进阶

- ILP/整数规划：将任务分配建模为约束优化问题。
- 局部搜索：在贪心解基础上做交换、迁移、合单调整。
- 多策略竞速：在 10 秒内并行/串行尝试多个策略，保留最优结果。
- LLM 辅助：让 LLM 根据样例特征选择策略或生成启发式参数，而不是直接求解大规模组合优化。
- 历史反馈：记录每类样例下各策略表现，下一轮自动调参。

## 两人分工建议

### 成员 A：算法与评分负责人

- 负责数据模型、评分函数、可行性判断。
- 实现贪心、局部搜索、ILP 等核心策略。
- 建立基准样例和单元测试。
- 对每轮算法结果做误差分析和性能优化。

### 成员 B：Agent 与工程负责人

- 负责 CLI、输入输出适配、配置管理和仓库工程化。
- 实现 Agent 策略选择、运行记录、超时控制和最佳解保留。
- 搭建实验脚本、日志和结果对比工具。
- 后续接入 LLM/规则调参模块。

## 里程碑

### M1：可运行 baseline

- 完成数据模型、评分、贪心策略、CLI。
- 能对样例输入输出合法方案。

### M2：多策略框架

- 加入策略注册与自动选择。
- 增加局部搜索或 ILP 原型。
- 建立实验结果记录。

### M3：Agent 迭代闭环

- 根据历史得分调整策略优先级。
- 支持多策略限时搜索。
- 输出最终最优方案。

### M4：比赛适配

- 对接官方数据格式。
- 压测 10 秒限制。
- 固化提交脚本和最终参数。
