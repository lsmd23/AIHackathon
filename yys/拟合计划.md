# 拟合官方评测数据 - 优化计划

## 目标

通过生成模拟数据、调试策略、分析官方样例特征，最终提升在官方评测上的分数。

---

## 1. 理解当前问题

### 核心挑战

- **不知道官方真实参数**（score分布、willingness分布、任务关系结构）
- **不知道评分函数精确公式**
- 只能通过"黑盒"猜测 + 反复提交试探

### 当前薄弱点

| 场景 | 现状 | 问题 |
|------|------|------|
| `low_willingness_seed501` | 分数~2800 | 意愿低导致期望分数高 |
| `scarce_couriers_seed401` | 分数~3200 | 骑手稀缺，冲突严重 |
| `large_seed301/302` | 分数~2800 | 大规模，局部搜索不够 |

---

## 2. 拟合策略框架

### 阶段一：逆向分析官方样例

**目标**：从现有官方样例反推隐藏参数

```
现有官方样例：
- tiny_seed42 (6任务)
- small_seed100 (15任务)
- medium_seed201/202/203 (30任务)
- large_seed301/302 (40任务)
- scarce_couriers_seed401 (40任务/44骑手)
- low_willingness_seed501 (30任务)
- high_noise_seed601 (30任务)
```

**分析维度**：

1. **score分布**
   - 均值、方差、分位数
   - 与task_count的关系
   - 与courier_count的关系

2. **willingness分布**
   - 分布形态（均匀/高斯/双峰）
   - 与score的相关性
   - 条件分布（给定bundle的willingness）

3. **候选结构**
   - 单任务 vs 合单比例
   - bundle多样性
   - courier复用程度

**执行**：
```bash
python scripts/profile_cases.py  # 已有脚本，分析样例特征
```

### 阶段二：参数化数据生成

**目标**：造一批"像官方"的数据用于调试

```python
# 生成参数
{
    "task_count": 30~50,
    "courier_ratio": 1.0~2.0,      # courier/task比例
    "score_mean": 20~80,
    "score_std": 5~30,
    "willingness_mean": 0.1~0.8,
    "willingness_distribution": "uniform" | "bimodal" | "low_biased",
    "pair_ratio": 0.7~0.95,         # 合单比例
    "noise_level": 0.0~1.0,
    "courier_specialization": 0.0~1.0,  # 骑手专业化程度
}
```

**生成脚本**：`scripts/generate_blackbox_like_examples.py` 已有，需增强参数化

### 阶段三：策略参数扫描

**目标**：在不同模拟数据上验证策略，找到最优参数组合

```python
# 参数网格
alpha: [0.5, 0.65, 0.85, 1.0, 1.2, 1.5]
max_couriers: [2, 3, 4, 5]
mode: ["expected", "assigned", "adaptive", "balanced"]
策略组合: [component_dp, hybrid_split, budgeted_pairing, low_beam, ...]
```

**评估指标**：
- 覆盖率（必须100%）
- 期望分数（本地计算）
- 与模拟"官方分数"的相关性

### 阶段四：对阵对抗训练

**目标**：造"最难的数据"训练策略鲁棒性

```
让当前策略在模拟数据上暴露弱点：
1. 高噪声数据 -> 验证排序策略稳定性
2. 双峰willingness -> 验证低意愿处理
3. 骑手稀缺 -> 验证冲突处理
4. 大规模 -> 验证时间限制
```

### 阶段五：官方分数回归分析

**目标**：找到本地指标与官方分数的关系

```
本地指标：
- expected_score（期望分数）
- assigned_score（已分配分数）
- willingness_weighted

官方分数 = f(本地指标) + 噪声

通过提交不同版本，拟合f的参数
```

## 5. 成功标准

1. **本地测试**：在模拟数据上找到明确的分数提升
2. **官方提交**：平均分数比当前提升 ≥5%
3. **鲁棒性**：不出现明显退化的情况

---

## 6. 注意事项

- 不要过拟合模拟数据，策略需要泛化
- 每次提交记录：参数、分数、样例特征
- 保持baseline可回退，不要覆盖主分支
- 时间限制10秒/算例，注意算法复杂度
